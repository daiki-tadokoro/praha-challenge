課題:GitHubのissueに誰かassigneeを割り当てるような状況を思い浮かべてください。
issueはassigneeが割り当てられていない状態で作成可能なため null になり得るようなカラムが、以下のような状態で定義されていたとします。

テーブル設計を見直して、Issueテーブルが null を含まないように作り変えてください。

<aside>
💡 新しくテーブルを作成する必要があるでしょう！

</aside>


### 案1 ダミーユーザを設ける

NULLを使わずに未アサインユーザ専用としてid=0みたいなのを作り
全てのユーザは何かしらのIDを持つ。


### 案2 中間テーブルを作る


- issuesテーブルからassignee_idを削除
- issue_assignmentsというテーブルで割り当てられる人を管理
- 割り当てがなければ中間テーブル(issue_assignments)にレコードが存在しない

```
CREATE TABLE issues (
    id SERIAL PRIMARY KEY,
    title TEXT NOT NULL
);

CREATE TABLE issue_assignments (
    issue_id INT PRIMARY KEY REFERENCES issues(id),
    user_id INT NOT NULL REFERENCES users(id)
);
```

### 果たしてNULLがデータベースに存在することは本当に悪いことか？

NULL自体が悪というより、NULLが持つ曖昧な意味やバグが起因の可能性として
リスクが高いため、なるべく使わないは正しそう。
