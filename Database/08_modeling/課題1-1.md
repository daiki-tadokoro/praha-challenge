## 課題1-1

企業Aのために自社の商品管理サービスを新たに作成することになり、商品テーブルを以下のように作成しました。

```sql
TABLE Product {
  productCode: varchar <- これがPK（主キー）
  name: varchar
}
```

ここで`productCode`が挿しているのは現在企業Aが用意している商品カタログにつけられている商品ごとのコードです。
例えば「A106=ネジ」とか「F980=ボルト」など、商品が識別できるようになっています。

企業Aの担当者に話を聞いたところ「商品コードを見れば商品を一意に特定できる」とのことでしたので、そのまま商品コードを主キーに使ってみました。

この対応にはどのような問題点が潜んでいるでしょうか？

### 商品コードを主キーに使用する問題点

#### 1. **ビジネスルールの変更への脆弱性**

**問題:**
- 商品コードの命名規則が変更された場合、既存データとの整合性が取れなくなる
- 例：「A106」→「A106-2024」のような変更が発生した場合

#### 2. **外部キー制約の問題**
- 商品コードが変更されると、関連テーブルの外部キー制約が破綻
- 大量のデータ更新が必要になり、パフォーマンスに影響

#### 3. **データ型の問題**
- `varchar`型の主キーは`int`型と比べてインデックス効率が悪い
- 文字列比較は数値比較より遅い

#### 4. **ビジネスロジックの複雑化**
- 商品コードの形式変更時に、システム全体への影響を考慮する必要
- 商品コードの重複チェックや形式検証が複雑

#### 5. **データ移行の困難さ**
- 他社システムとの連携時に、商品コードの形式が異なる場合の対応が困難
- 例：企業A「A106」、企業B「A106-001」
